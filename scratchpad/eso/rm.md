This README provides a step-by-step guide to synchronizing secrets from **Azure Key Vault (AKV)** into your **Kubernetes** cluster using the **External Secrets Operator (ESO)** with **User-Assigned Managed Identity (UAMI)** authentication.

---

# 🛡️ Kubernetes Secrets: Azure Key Vault & ESO Integration

This repository outlines the workflow for securely fetching secrets from Azure and mounting them into your application pods.

## 🏗️ The Architecture

The flow follows this logic:

1. **Azure Key Vault** stores the sensitive data.
2. **UAMI** provides the identity for the Kubernetes nodes/pods to talk to Azure.
3. **SecretStore** defines *how* to authenticate with Azure.
4. **ExternalSecret** defines *what* specific secret to fetch.
5. **Kubernetes Secret** is automatically generated by ESO.
6. **Pod** mounts that secret as a volume or environment variable.

---

## 🛠️ Prerequisites

* **External Secrets Operator** installed in your cluster.
* An **Azure Key Vault** with a secret created (e.g., `db-password`).
* A **User-Assigned Managed Identity (UAMI)** with `Key Vault Secrets User` permissions on the Vault.
* **Workload Identity** configured (recommended) or the UAMI assigned to the VMSS of your AKS nodes.

---

## 🚀 Step-by-Step Implementation

### 1. Create the SecretStore

The `SecretStore` tells the operator how to find your Azure Key Vault. Using a UAMI via Workload Identity is the most secure method.

```yaml
apiVersion: external-secrets.io/v1beta1
kind: SecretStore
metadata:
  name: azure-store
spec:
  provider:
    azurekv:
      authType: WorkloadIdentity
      vaultUrl: "https://<your-key-vault-name>.vault.azure.net"
      serviceAccountRef:
        name: eso-service-account # The SA linked to your UAMI

```

### 2. Define the ExternalSecret

This resource tracks the secret in Azure and creates a native Kubernetes Secret.

```yaml
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: my-app-db-password
spec:
  refreshInterval: 1h
  secretStoreRef:
    kind: SecretStore
    name: azure-store
  target:
    name: k8s-db-secret # The name of the secret created in K8s
    creationPolicy: Owner
  data:
  - secretKey: password # Key inside the K8s secret
    remoteRef:
      key: db-password   # Name of the secret in Azure Key Vault

```

### 3. Mount the Secret into a Pod

Once the `ExternalSecret` status is `SecretSynced`, you can mount the resulting `k8s-db-secret` into your deployment.

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  template:
    spec:
      containers:
      - name: app-container
        image: my-app-image
        volumeMounts:
        - name: secret-volume
          mountPath: "/etc/secrets"
          readOnly: true
      volumes:
      - name: secret-volume
        secret:
          secretName: k8s-db-secret

```

## 🔍 Verification Commands

| Action | Command |
| --- | --- |
| **Check ESO Status** | `kubectl get externalsecret my-app-db-password` |
| **View Created Secret** | `kubectl get secret k8s-db-secret -o yaml` |
| **Verify Pod Mount** | `kubectl exec <pod-name> -- ls /etc/secrets` |

> [!IMPORTANT]
> Ensure your **User-Assigned Managed Identity** has the `Client ID` properly mapped in the ServiceAccount annotations if you are using Azure Workload Identity.
