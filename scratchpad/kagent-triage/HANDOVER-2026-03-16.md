## What Was Done

### 1. Fixed Workflow Template — Session API → A2A Protocol

The `create-conversation` step in the `kagent-triage` WorkflowTemplate was broken. The session-based API (`/api/sessions/{id}/events`) fails with `user_id is required` or `403 Forbidden` on kagent v0.8.0-beta4.

**Fix:** Rewrote the step to use the **A2A (Agent-to-Agent) protocol** which is the correct way to invoke kagent agents:

```
POST /api/a2a/kagent/{agent-name}/   (trailing slash REQUIRED)
Body: JSON-RPC 2.0 with method "message/send"
Parts must include "kind": "text"
```

**File:** `02-workflow-kagent-triage.yaml` — the `create-conversation` template was completely rewritten.

## Key Findings

### 1. Session API is broken — use A2A instead
The `/api/sessions/{id}/events` endpoint in kagent v0.8.0-beta4 has an auth middleware issue. The `user_id` must be passed as a query parameter AND must match the session owner, but it still returns 403. The A2A protocol (`/api/a2a/kagent/{agent}/`) works reliably and is simpler.

### 2. A2A message format requires `kind` field
```json
{"kind": "text", "text": "message"}  // Correct
{"text": "message"}                   // Wrong - "unsupported part kind"
```

### 3. Kyverno installs a `require-labels` policy by default
This generates Warning events for every pod without an `app` label. The kyverno-agent correctly identified this as the root cause when events fired.

### 4. cert-manager agent has admin tools
The cert-manager agent was deployed with write tools (from a previous session). It successfully auto-patched the cainjector deployment with resource limits. Other agents are read-only.

### 5. Token budget
Total LLM calls this session: ~8 (well within budget for testing 5 namespaces).
